# 信匣 · Xinbox SMS Platform

多账号、多号码的短信和来电聚合管理平台。后端 FastAPI，前端 Vue 3，SQLite 加密存储，支持 Docker Compose 部署。

## 功能

- 用户自行注册、用户端与管理端权限隔离、号码归属分配。
- 短信查询、搜索、归档、敏感正文保护；来电事件聚合。
- 多渠道自动转发、筛选和模板、持久化队列、失败重试及投递日志。
- Telegram、企业微信应用/群机器人、钉钉、飞书、Bark、Server酱、PushPlus、ntfy、Gotify、SMTP、自定义 Webhook。
- 企业微信应用指令在对应转发渠道内配置，继承号码范围和权限，支持独立应用回调。
- 号码回收站、接收服务控制、站内公告与注册设置。

## 目录

```text
backend/       FastAPI、权限、加密记录、转发及应用指令
frontend/      Vue 3 管理界面与用户界面
collector/     C++ 接收适配器及加密落库组件
tools/         服务控制与数据同步工具
deploy/        systemd、离线镜像及企业微信桥接适配
compose.yaml   容器配置
```

## 构建前端

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm run build
```

## 部署说明

本仓库是源码快照，**不包含生产数据、账号凭据、第三方 SDK 二进制或私有协议配置**。复制源码本身不会自动获得无忧行短信接收能力。

1. 准备 Linux 环境、Docker Compose，以及本人持有或明确获授权的号码。
2. 获取合法可用的采集依赖及外部 SDK，参考 `collector/build_receiver.sh`；生产部署所需的私有协议/会话配置须自行提供。
3. 按 `compose.yaml` 配置数据源目录、管理员初始密码文件和企业微信回调桥接文件。文件中不得填入或提交真实密钥到 Git。
4. 构建前端，再构建/启动后端容器。未接入现有企业微信回调服务时，应移除对应桥接文件挂载；独立企业微信应用回调可在渠道中配置。
5. 公网访问使用 HTTPS；`/admin` 为管理员入口，`/app` 为用户入口。

`tools/prepare_server.py` 与 systemd 模板采用 `/opt/jego-*` 目录约定，部署前需核对路径。完整开发记录与限制见 [实现说明](docs/IMPLEMENTATION_NOTES.md)。部分历史说明反映早期阶段，实际行为以当前源码为准。

## 注意

- 网页和管理员接口已增加归属校验，当前仓库尚未附带完整自动化测试。
- 来电来自采集事件，不代表运营商完整历史清单；接收器存活也不保证投递成功。
- 删除号码保留历史与加密会话，可在回收站恢复；不自动修改无忧行托管开关。
- 仅限本人或明确授权管理的号码，不得绕过第三方认证或安全机制。
- 未指定开源许可证；第三方 SDK/组件按其各自许可使用。
